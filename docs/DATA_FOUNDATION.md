# Первый этап: данные и сохранение

27 октября 2026 года. Ветка `fix/data-persistence`.

## Инфраструктура

Проект Supabase `wsmpooyesdmcuiznemry` восстановлен из состояния `INACTIVE`. После восстановления API управления сообщает `ACTIVE_HEALTHY`, таблицы доступны. Пять миграций из исходного репозитория присутствуют в базе.

Применена миграция `20261027190721_enforce_note_book_ownership`: проверяется не только владелец заметки, но и владелец связанной книги. Создание заметки к чужой книге отклоняется RLS. Обновлён и канонический файл `supabase/schema.sql`.

## Изменения приложения

- Прогресс книги сохраняется отдельно от заметок. Перелистывание не отправляет заметки повторно.
- Книги и заметки получают UUID до запроса. Повторное сохранение того же черновика использует тот же ID.
- Читалка и библиотека показывают подтверждённое сервером состояние. На время записи повторные действия блокируются. При ошибке остаются прежняя позиция и текст черновика; ошибку видно в интерфейсе.
- Удаление заметки выполняется отдельным запросом с ID заметки, книги и владельца, затем обновляется интерфейс.
- Публичный профиль загружается отдельным запросом, без личных книг, цитат и email. При смене профиля устаревший ответ игнорируется.
- Лента и рейтинг обрабатывают ошибки независимо; добавлена повторная загрузка. Ошибки публикации, лайков и комментариев отображаются пользователю.
- XP после действий считывается из базы, где начисляется триггерами. Клиент больше не прибавляет опыт самостоятельно.
- Случайный календарь активности и фиктивное время чтения удалены из профиля. Статистика показывает существующие книги и заметки; учёт сессий чтения остаётся отдельной задачей.
- Удалена неработающая кнопка коллекций. Удалён анимированный шум поверх интерфейса: внешний ресурс возвращал HTTP 402, а пробная встроенная замена давала слишком заметную зернистость.
- Добавлены инструкции запуска, локальные тесты и отдельная проверка данных с явным включением записи в удалённый проект.

## Проверено

### Локальные тесты

`npm test`: 7 тестов. Повторное сохранение заметки и книги, перелистывание без записи заметок, удаление с фильтрами владельца, распространение ошибок записи и загрузка публичного профиля без приватных таблиц.

### Реальный Supabase

`BOOKNOOK_ALLOW_REMOTE_TESTS=1 npm run verify:data`:

- Регистрация двух временных аккаунтов.
- Повторное создание книги и заметки без дублей.
- Запись прогресса и восстановление после повторной загрузки.
- Запрет второму пользователю читать чужие книги и заметки или менять чужую книгу.
- Запрет добавления заметки к чужой книге.
- Публичный профиль доступен гостю и другому пользователю, email не возвращается.
- Удаление заметки и книги, обновление счётчика завершённых книг.
- Удаление тестовых аккаунтов через Edge Function вместе с их данными.

### Браузер

Проверена регистрация через форму и добавление книги вручную. Для сохранения заметки и прогресса принудительно возвращался HTTP 503: ошибка отображается, текст заметки остаётся в форме, позиция не меняется до успешного ответа. Повторная попытка сохраняет одну заметку; после перелистывания и перезагрузки остаются третья страница и одна заметка. После удаления заметка не возвращается при перезагрузке.

Отдельно проверены сбой рейтинга при работающей ленте, сбой ленты при работающем рейтинге и восстановление кнопкой повтора. Гость открывает публичный профиль без доступа к личной статистике.

Публикация цитаты и записи в ленте проверена через интерфейс: опыт в профиле обновился до серверных 30 и 50 XP соответственно. Удаление временного аккаунта через форму профиля прошло успешно; все созданные для проверки аккаунты и их данные удалены.

## Следующие задачи

- Правильный порядок глав EPUB по пакету книги, проверка импорта PDF и TXT.
- Реальные сессии чтения, календарь, время и статистика за выбранный год.
- Коллекции как полноценная функция.
- Обработка ошибок и повторных действий в The Grid, проверка остальных мобильных сценариев.
- Обновление зависимостей перед выпуском: исходный `npm audit` сообщает 11 уязвимых пакетов, включая два critical в Android/инструментах. Отдельная сборка Android в этом этапе не проверялась.
- Supabase advisors сообщает, что [защита от скомпрометированных паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) выключена. Настройка аккаунта не изменялась.

Изменения интерфейса находятся локально; публикация на Vercel и отправка ветки в GitHub в этот этап не входят. База восстановлена, миграция прав доступа уже применена к существующему Supabase-проекту.

## Адаптация вёрстки

Исправлено переполнение главной страницы: приветствие и карточка уровня перестраиваются по доступной ширине содержимого. Убраны жёсткие минимальные ширины, уменьшены отступы в узких карточках, добавлены переносы длинных названий. Боковое меню отображается с 1024 px, на более узких экранах используется нижняя навигация.

Профиль, фильтры библиотеки и карточки сообщества адаптированы к узким экранам. В читалке панель заметок сворачивается до 1280 px; панели настроек, форма заметки и переключение страниц ограничены шириной окна. Диалоги вынесены в порталы в `document.body`, ограничены высотой экрана и прокручиваются внутри, чтобы меню и анимации страницы не смещали и не перекрывали их.

Проверка в браузере: пять основных разделов на ширинах 320, 390, 640, 768, 1024, 1280, 1440 и 1920 px без горизонтального переполнения. Дополнительно проверены длинные названия, цитаты и ссылки на временных ответах API только в проверочном браузере, без записи в базу. Шесть панелей и форм проверены при 1280×800, 768×600, 390×844 и 320×568: их границы остаются внутри экрана. Временные ответы API после проверки отключены. Production-сборка проходит.
